# Fleet：跨空间发现 / 登记表 / 批量初始化

## 原则

**跨空间只读** —— fleet 只做发现与策展，不修改其他工作区的台账；要改，进那个工作区改。
唯一例外：用户明确要求「给每个工作空间建台账」时的批量初始化（见文末）。

## discover —— 发现工作区

```bash
python <技能目录>/scripts/discover_ws.py --config <data_home>/config.json
```

- 权威来源：当前 runtime 会话目录下 jsonl 记录的 `cwd` 字段（多 runtime 自适应，见脚本 docstring）
- **为什么不用扫目录**：工作区可能在任何位置，目录名反推路径有歧义；`cwd` 是精确的
- 脚本**不过滤、只打标签**：`<时间戳>`（正则 `^\d{4}-\d{2}-\d{2}-\d{2}-\d{2}-\d{2}$`）与 `<已删除>` —— 让你看到有什么再决定
- 未知 runtime → 脚本退出并提示；此时**登记表手工策展**，不硬猜目录结构

## registry —— 维护登记表

`<data_home>/workspaces.md`：**自动发现只给候选，登记表做策展**。

```markdown
## 纳入汇总
| 别名 | 路径 | 主题 | 台账 |
|---|---|---|---|
| **别名** | `绝对路径` | 一句话主题 | ✅ N 项目 / M 任务（或 ❌） |

## 排除
| 路径 | 原因 |
|---|---|
```

- 登记表不存在 → 跑 discover 生成初稿，**请用户确认后再写盘**
- 发现新候选 → 提示用户是否纳入，**不自动加**
- 用户说「不纳入某个」→ 移到排除段并写原因
- 排除候选：时间戳目录、路径已不存在的

## 看板刷新

跨空间汇总的唯一产物是 `<data_home>/board.html`，唯一生成入口：

```bash
python <技能目录>/scripts/refresh_board.py --config <data_home>/config.json
```

- 由晨间定时任务自动执行；用户急看时**重跑该任务或此脚本**，不在对话里手算汇总
- 汇报口径：先给"共 N 个工作区，M 个有台账，合计 X 项未完成，Y 项等外部"；
  **区分「无台账」（缺数据）与「无未完成事项」（真清空）**
- 跨空间瓶颈的**综合归纳**（同一瓶颈压着多个空间时）在对话里补，不落盘
- 不下"你应该先做哪个空间"的判断 —— 那是用户的取舍

## 批量初始化

用户说「给每个工作空间建台账」时即走此路径（**这不是普通 fleet 操作**——是逐个空间执行初始化）：

1. discover + 读登记表，拿到纳入清单
2. 逐空间读一手材料（日志 / README 待办节）→ 聚合事项
3. 逐空间落盘（`tasks/` 卡片 → `TASKS.md` → IDE 上下文文件节 → `.taskboard/config.json` 指针），步骤见 `references/setup.md` 第二节
4. 全部完成后才跑 `refresh_board.py`（此时各空间台账已齐，看板才准确）
5. 报告里**分开写**「新建了哪几个」与「刷新了哪几个」

**三种常见缺失**（批量初始化时逐一确认）：

| 缺失 | 处置 |
|------|------|
| 工作区无 IDE 上下文文件（`CODEBUDDY.md` / `CLAUDE.md` / `CODEX.md`） | 按当前平台建最小版：抬头指向权威导航 + 空间定位一段 + 「任务台账」节（缺它则该空间无项目级上下文注入） |
| 工作区无一手材料可读 | 只建骨架，卡片留空待用户口述，**不编造** |
| 工作区已有其他插件标记段 | 「任务台账」节追加到文件尾部，不动标记段 |
