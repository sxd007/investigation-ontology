# 下班收尾（EOD wrap）

由定时任务在下班前触发（默认工作日 18:00）。**只管当前 agent 所管理的工作区**（多 agent 并用时各自收尾各自的空间，次日晨刷做全局合并）。

## 输入

- 当前 agent 当天的会话记录（runtime 会话目录，与 `discover_ws.py` 同一来源）
- 各工作区 `.taskboard/tasks/` 卡片现状
- `<data_home>/config.json`（路径与阈值）

## 步骤

1. **圈定范围**：读 `<data_home>/workspaces.md` 纳入段，过滤出今天有会话活动的工作区
   （按会话 jsonl 的修改时间 / cwd 归属判断；当前 agent 触不到的空间不碰）
2. **读当天会话**：提取每个活跃空间今天实际推进了什么——哪些事项有进展、卡在哪、新冒出了什么待办
3. **回写卡片**（遵守 SKILL.md 纪律）：
   - 有进展的卡 → 更新「进度」/「已完成」+ frontmatter `updated`，并把会话标识追加进 `sessions`
   - 新冒出的待办 → 按 `references/card-maintenance.md` 建卡（必填三项从会话材料抽取；**抽不齐的留空并在收尾小结里问用户**，不编造；`def_source` 如实标 `extracted`/`inferred`）
   - 状态变化（如某卡今天被外部卡住了）→ 改 `status` 并写清「阻塞 / 待外部」
   - 没有推进的卡**不动**（不为了显得有产出而改写）
4. **同步**：项目卡子项表 → 跑 `refresh_board.py --write-tasks-md`（看板与各空间 TASKS.md 一并重生成）
5. **跑 `audit_tasks.py`** 逐个改动过的空间校验，有问题当场修
6. **输出收尾小结**（对话内，不落盘）：
   - 今天推进了哪几张卡（一句话/张）
   - 新建了哪几张卡（含必填三项留空待用户补的，**逐条列出问用户**）
   - **定义未确认卡清单**：把所有 `def_source` 非 `user` 的卡（含存量）的三项压缩成清单，**批量请用户确认**；确认的卡改 `user` + `def_confirmed`
   - 哪些卡仍然卡着、卡在谁那里
   - 明天最值得续接的 1–3 项（含下一步动作）

## 边界

- 只做增量收尾，**不重构**台账（提升为项目、批量回填属于用户触发的维护动作）
- 会话里涉及未脱敏案件材料的内容**不进卡片**
- 当天零活跃空间 → 小结一句"今天无推进"，不硬凑
- 定时任务不可用时（如用户手动触发本流程），流程不变
