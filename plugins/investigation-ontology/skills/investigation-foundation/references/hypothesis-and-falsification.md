# 假设生成与证伪

本参考用于需要展开假设类型、检查覆盖面或设计区分性验证时。主流程和强制约束见上级 `SKILL.md`。

## 最小充分竞争假设集

假设集应足以覆盖当前调查问题中合理且可区分的解释，但不追求数量。通常保留 3-5 个活跃假设；简单问题可以更少，复杂案件可以更多。以下五类是**覆盖检查面**，不是“每类必须生成 1-2 个”的配额：

| 类型 | 核心问题 | 常见子类 |
|---|---|---|
| 行为 Action | 发生了什么 | 事实、过程、程度、时间 |
| 动机 Motive | 为什么发生 | 利益、压力、合理化 |
| 机会 Opportunity | 如何成为可能 | 控制缺口、权限、信息不对称 |
| 关系 Network | 谁参与或受益 | 直接参与、共谋、知情、受益 |
| 影响 Impact | 造成什么后果 | 财务、非财务、蔓延风险 |

与当前调查问题无关的类别可以标记“不适用”，但应说明理由。

## 替代假设的要求

初始假设不得全部支持举报或指控。至少保留一个真正挑战核心命题的合理替代解释，并以同等优先级验证。合格的替代假设包括：

- 举报所述行为未发生；
- 异常来自正常业务例外、流程设计或数据质量问题；
- 行为发生，但责任主体、范围、金额或时间不同；
- 行为发生，但现有材料不足以证明主观故意；
- 多个原因共同造成观察结果。

“举报人动机不纯”本身不是“举报不真实”的替代假设。除非举报人动机与信息真实性存在可验证关联，否则不得用来源偏见替代对核心命题的验证。

## 把假设写成可验证命题

每项假设应满足：

1. 陈述具体的主体、行为、对象、时间或范围；
2. 可以被未来证据支持或反驳；
3. 不把法律结论或道德评价预先写入事实命题；
4. 与其他假设存在至少一个可区分的预测。

不良示例：“张三肯定舞弊。”

改进示例：“2026 年第一季度，张三是否在明知终端客户信息不真实的情况下批准了订单 O-123？”

## 验证矩阵

对每个假设记录：

| 项目 | 问题 |
|---|---|
| 支持性预测 | 如果假设为真，预计会观察到什么？ |
| 反驳性预测 | 什么结果会显著降低该假设？ |
| 区分性证据 | 哪项证据最能区分相互竞争的解释？ |
| 主路径 | 首选获取方式是什么？ |
| 备用路径 | 主路径不可用时如何替代？ |
| 阶段限制 | 当前阶段是否允许获取，是否会接触涉案方？ |
| 缺口影响 | 获取失败会削弱哪些判断？ |

优先获取区分力高、易灭失、当前阶段允许且对多个假设都有信息价值的证据。

## 常见失败模式

- 把调查事项清单误写成假设；
- 只生成指控性解释；
- 用五类配额制造大量低价值假设；
- 只列支持证据，不定义反驳条件；
- 新证据到达后只更新领先假设；
- 用举报人的身份或动机替代内容核实；
- 把“尚未发现反证”当作“已经证实”。
