# 证据规则

## 证据收集
1. 所有证据收集必须合法合规，不得使用非法手段取证
2. 优先收集原件，无法取得原件时标注复制件来源和原因
3. 电子证据收集时必须记录元数据和哈希值
4. 证据收集过程必须全程记录，包括时间、地点、人员、方法

## 证据保全
5. 每件证据必须有完整保管链记录
6. 电子证据必须做写保护处理后再分析
7. 证据存放环境必须符合安全管理要求
8. 证据的每次移交必须双人见证并签字

## 证据评估
9. 证据可采性评估必须遵循: 相关性 → 合法性 → 可靠性 → 最优证据原则
10. 单一证据不能独立支撑核心结论, 需多源印证
11. 矛盾证据必须记录, 不能选择性忽略
12. 证据充分性使用 SPIRIT 框架判断

## 主张溯源与信源标注

每项关键事实主张必须可追溯到证据 ID 或原始来源。标注时区分两个维度，不得混为同一枚举：

| 维度 | 可用值 | 说明 |
|---|---|---|
| 陈述性质 | `firsthand` / `relay` / `opinion` / `attitude` / `inference` | 信息是亲历、转述、意见、态度还是分析推论 |
| 核实来源 | 举报 / 系统 / 文件 / 访谈 / 公开来源 / 调查分析 | 信息通过何种来源获得或核实 |

13. 举报信息必须标注 `[举报人称]`，不得直接引用为已确立事实
14. 系统、文件、访谈和公开来源应记录具体来源、获取时间和获取方式
15. 分析判断使用 `[分析判断]` 或 `inference`，不得伪装成事实或替代证据链
16. 同一原始来源衍生的多份材料不得视为独立印证
17. 当前 Schema 中的 `source` 字符串应同时保留足够的来源细节；展示前缀不是结构化证据登记的替代品

## 证据缺口

18. 信息缺口首先表示“不知道”，不得自动视为不利事实
19. 调查方因权限、技术或工作不足未获取的信息，应记录为调查方缺口，并评估是否降低相关 finding 的置信度
20. 客观条件导致不可获取的信息，应记录为环境缺口和替代获取路径
21. 当事方未提供材料时，应记录请求内容、提供义务、期限、回应和客观障碍；默认先作为配合风险信号，不自动证明相关指控或提高 finding 置信度
22. 仅在存在明确保存或提供义务、请求合理、期限充分、客观原因已排除并经授权复核后，才可讨论有限不利推定
23. 缺口归因不明确时采用保守处理，不得默认用于强化嫌疑

## 保密
24. 证据访问遵循"知情人最小化"原则
25. 电子证据文件必须加密存储
26. 所有证据必须标明密级
